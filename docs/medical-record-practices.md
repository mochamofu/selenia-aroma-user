# 電子カルテの考え方を取り入れる方針

作成日: 2026年8月17日
目的: 顧客の機密情報の扱いを、医療機関で使われている電子カルテの運用に寄せる

## 前提の整理

当サービスは医療機関ではなく、画面内の「診断」も香り提案・測定結果整理の業務表現である。
そのため医療法・医師法にもとづく診療録の規制がそのまま適用されるわけではない。

一方で、持病・服薬状況・体調といった情報を記録している。これらは個人情報保護法上の
**要配慮個人情報**にあたり、次の制約がかかる。

- 取得にあたって本人の同意が必要
- 第三者提供でオプトアウト（本人が拒否しない限り提供してよい形）は認められない
- 漏えい時は個人情報保護委員会への報告と本人への通知が必要

医療機関向けの仕組みをそのまま真似る必要はないが、**扱っている情報の性質は近い**ため、
実績のある考え方を部分的に取り入れる。

## 参考にする公開情報

電子カルテ製品の中身は公開されていないが、満たすべき要件は公開されている。

- 厚生労働省「医療情報システムの安全管理に関するガイドライン」
- 電子保存の三原則（真正性・見読性・保存性）
- 個人情報保護法における要配慮個人情報の取り扱い

## 取り入れる項目

### 実装済み

| 項目 | 電子カルテでの考え方 | 当サービスでの実装 |
| --- | --- | --- |
| 閲覧の記録 | 誰がいつ誰のカルテを見たかを残す | `audit_logs`。事業者が顧客の記録・ヒアリング・内部配合を開くと自動で記録される |
| 記録は追記のみ | 監査証跡は消さない | `audit_logs` は更新・削除を行わない |
| 同意の記録 | 説明と同意を記録に残す | `consents`。撤回時も行は消さず `revoked_at` を入れる |
| 最小権限 | 職種ごとに見える範囲を分ける | `src/server/db/access.ts`。顧客は自分の公開済みのみ、事業者は全件 |
| 他患者の情報を出さない | 画面に他人の氏名を残さない | カルテの顧客リストを既定で閉じ、選択すると自動で閉じる |
| 患者の同定 | 患者番号で一意に識別する | 8桁の顧客番号（店舗2桁＋年度2桁＋連番4桁） |

閲覧の記録は、呼び出し側が書き忘れられないよう**リポジトリ層の内部で行っている**。
画面から個別に記録を呼ぶ作りにすると、必ずどこかで漏れる。

### 未実装（今後の候補）

| 項目 | 電子カルテでの考え方 | 当サービスで想定する形 |
| --- | --- | --- |
| 記録の訂正 | 上書きせず、訂正履歴を残す（真正性） | カルテの更新を版として積み、前の内容と変更者を残す |
| 自動ログアウト | 離席時の覗き見を防ぐ | 一定時間操作がなければ画面をロックする。店舗の共用端末では効果が大きい |
| 取り違え防止 | 氏名・生年月日・患者番号で複数確認 | 測定開始前に顧客番号と氏名を突き合わせる確認を挟む |
| 通常範囲外のアクセス | 理由を入力させ、後から監査する | `audit_logs.reason` の入力欄は用意済み。入力を促す画面が未実装 |
| 保存期間と削除 | 保存年限を定めて運用する | 退会時の削除方針、脳波画像の保管期間を決める |
| 本人への開示 | 患者が自分の記録の開示を請求できる | `listAuditForSubject` で、誰が自分の情報を見たかを返せる形にしてある |

## 注意

医療機関で使われている考え方を取り入れるが、**医療行為・医療機器・診療録であるかのような
表示や説明はしない**。画面上の表現は従来どおり、香り提案と測定結果の整理として扱う。
