# 顧客番号（カルテ番号）仕様

作成日: 2026年8月17日
対象: 購入者向けアプリ（本リポジトリ）と、インストラクター向け管理アプリ（別リポジトリ）
位置づけ: 2つのアプリで共通して使う顧客識別子の採番ルール

## 1. 方針

購入者向けアプリと、インストラクター向け管理アプリで、同一の顧客を同一の番号で参照する。
この番号を「顧客番号（カルテ番号）」と呼び、両アプリの表示・検索・データ連携の共通キーとして扱う。

内部の主キーは引き続きUUID（`profiles.user_id`）を使用し、顧客番号は人間が読み書きするための業務キーとして併用する。

## 2. 採番ルール

顧客番号は8桁の数字とする。

```
[店舗番号 2桁][年度 2桁][店舗内連番 4桁]
```

| 区分 | 桁数 | 内容 |
| --- | --- | --- |
| 店舗番号 | 2 | 店舗ごとに割り当てる固定番号。例: 銀座店 = `01` |
| 年度 | 2 | 登録年の西暦下2桁。例: 2026年 = `26` |
| 店舗内連番 | 4 | その店舗・その年度で登録した順番。`0001` から開始 |

### 例

`01260051`

- `01`: 銀座店
- `26`: 2026年
- `0051`: 銀座店で2026年に51番目に登録した顧客

### 採番の単位

連番は「店舗ごと・年度ごと」にリセットする。
店舗をまたいで通し番号にはしない。年度が変わったら `0001` に戻す。

### 上限

1店舗・1年度あたり9999人まで。超過する見込みが出た時点で桁数の拡張を検討する。

## 3. 店舗番号の管理

店舗番号は両アプリで共通の台帳とする。番号は一度割り当てたら再利用しない。

| 店舗番号 | 店舗名 |
| --- | --- |
| 01 | 銀座店 |

（店舗追加時にこの表へ追記する）

## 4. データ設計

### 購入者向けアプリ（本リポジトリ）

`profiles` に顧客番号カラムを追加する想定。

```sql
alter table public.profiles
  add column if not exists customer_number char(8);

alter table public.profiles
  add constraint profiles_customer_number_format
  check (customer_number ~ '^[0-9]{8}$');

create unique index if not exists profiles_customer_number_idx
  on public.profiles(customer_number);
```

顧客番号は購入者向けアプリでは表示・参照のみとし、採番はインストラクター向け管理アプリ側で行う。
購入者向けアプリから採番・変更はしない。

### 全体管理

顧客番号の一覧・重複チェック・店舗横断の集計は、ユーザー管理アプリ側で担当する。
本リポジトリでは、割り当て済みの番号を保持・表示することのみを責務とする。

## 5. 実装

パース・生成・検証のユーティリティを `src/lib/customerNumber.ts` に置く。
インストラクター向け管理アプリでも同じルールを実装し、両者で挙動を一致させる。

## 6. 表示上の扱い

- 購入者向け画面ではマイページなどに「会員番号」として表示する
- 8桁をそのまま表示する。区切り文字は入れない
- 未採番の顧客は表示しない（空欄にする）
