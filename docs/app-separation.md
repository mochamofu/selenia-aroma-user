# 購入者向けと管理者・事業者向けの書き分け

作成日: 2026年8月17日
目的: 管理者・事業者向けの改修が購入者向け画面に影響しないようにする

## 方針

購入者向け画面と管理者・事業者向け画面は、同じNext.jsアプリの中で別系統として扱う。
管理者側の改修で購入者側の表示が変わってしまう状態を避けるため、外枠とナビゲーションを系統ごとに分ける。

## ディレクトリの区分

| 置き場所 | 対象 | 変更時の影響 |
| --- | --- | --- |
| `src/components/customer/` | 購入者向け専用 | 購入者側のみ |
| `src/components/admin/` | 管理者・事業者向け専用 | 管理者側のみ |
| `src/components/` | 両系統が使う共通部品 | **両方に影響する** |
| `src/lib/customerNav.ts` | 購入者向けタブ定義 | 購入者側のみ |
| `src/lib/adminNav.ts` | 管理者向けタブ定義と活性判定 | 管理者側のみ |

## 外枠（シェル）

系統ごとに別コンポーネントとする。共通の`AppShell`は廃止した。

| シェル | 使う画面 | レイアウト |
| --- | --- | --- |
| `customer/CustomerShell.tsx` | `/dashboard` `/aromas` `/moods` `/oils` `/base-blends` `/profile` | 430px固定、ボトムナビ |
| `admin/AdminShell.tsx` | `/admin` 配下 | 768px以上でサイドナビ、未満でボトムナビ、最大1180px |
| （シェルなし） | `/operator` | ページ内で独自のサイドバーを持つ |

購入者向けはスマートフォン前提の430px固定を維持する。PC・タブレット対応は管理者・事業者側のみで行う。

## 共通部品の扱い

`src/components/` 直下の部品は両系統から使われるため、**変更すると購入者側の表示も変わる**。

| 部品 | 使う系統 |
| --- | --- |
| `Icon.tsx` | 両方 |
| `States.tsx` | 両方 |
| `AromaImage.tsx` | 両方 |
| `AromaCard.tsx` | 両方 |
| `FavoriteButton.tsx` | 両方（`AromaCard`経由） |
| `QuickActionCard.tsx` | 両方 |

管理者側だけで見た目を変えたい場合は、共通部品を書き換えるのではなく `src/components/admin/` に専用の部品を作る。

### 把握している課題

`AromaCard` は購入者向けのカード（お気に入りのハート付き）を管理者のアロマ記録一覧でも使っている。
管理者画面でお気に入りの切り替えが出るのは用途として不自然なため、管理者用のカードを分けるのが望ましい。
表示の挙動が変わる変更になるため、このドキュメントでは課題として記載するにとどめる。

## データの区分

| データ | 置き場所 | 用途 |
| --- | --- | --- |
| `src/data/operatorCustomers.ts` | 事業者側の顧客マスタ | カルテ、顧客一覧、ダッシュボードの顧客数 |
| `src/data/mockData.ts` | 購入者向けデモデータ | 購入者画面、アロマ記録 |
| `src/data/essentialOils.ts` | 精油図鑑 | 両方 |

## ルーティングの出し分け

`NEXT_PUBLIC_APP_TARGET=customer` のとき、`src/proxy.ts` が `/admin` と `/operator` へのアクセスを
`/dashboard` へリダイレクトする。購入者向けの公開URLでは管理画面を開けない。

## 変更時の確認

購入者向け画面に手を入れていないつもりの変更でも、共通部品に触れた場合は購入者側を確認する。

```bash
npm run dev:3100
```

`/dashboard` `/aromas` `/profile` を430px幅とPC幅の両方で開き、シェル幅が430pxのままでボトムナビが出ていることを確認する。
