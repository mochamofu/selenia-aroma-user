# 脳波アロマ事業者向け管理アプリ 現行仕様書

作成日: 2026年7月7日  
対象画面: `/operator`  
対象アプリ: Selenia Aroma / Next.js Webアプリ  
位置づけ: 事業者向けカルテ管理デモ。正式運用前の画面確認・業務要件整理用。

## 1. 概要

本画面は、脳波アロマ測定を行う事業者が、利用者ごとの1分測定データ、脳波グラフ画像、事前ヒアリング回答、香り制作記録、過去の制作履歴、ベースブレンド情報、追加精油情報を一元管理するためのWeb管理画面である。

利用者は「患者」ではなく、アロマ測定サービスの利用者・顧客として扱う。画面内の「診断」は香り提案・測定結果整理の業務表現であり、医療診断を意味しない。

## 2. 現在の提供形態

- 起動URL: `http://localhost:3000/operator`
- 実装ファイル: `src/app/operator/page.tsx`
- フレームワーク: Next.js 16.2.6
- React: 19.2.4
- UI: Tailwind CSS 4系のユーティリティクラス
- アイコン: lucide-react
- データ: 現時点ではモックデータとブラウザ内状態
- 永続化: 未実装。ページ再読み込みでアップロード画像・保存ドラフトは消える

## 3. 対象ユーザー

### 3.1 事業者オペレーター

主な操作:

- 利用者カルテを選択する
- 過去の香り診断・制作履歴を確認する
- 履歴に紐づく脳波画像を大きく確認する
- 脳波画像にタイトルとメモを付ける
- 香り制作記録を作成・編集する
- Googleフォーム等で取得した事前ヒアリング回答を制作履歴ごとに確認する
- 妊娠中、出産直後、妊活中、授乳中、持病、服薬などの禁忌・注意フラグを確認する
- 5mLまたは10mLなど完成量に応じて配合量を確認する
- ベースブレンドと追加精油の情報を確認する

### 3.2 管理者

現行デモでは、ベースブレンドの構成精油、内部比率、事業者用メモのみ簡易的な管理者解除で表示を分けている。本番化時には、顧客情報・制作履歴・画像・オイルDBの編集権限をログイン権限で分離する。

## 8. 香り制作記録仕様

### 8.1 入力項目

- 制作名
- 制作日
- ベースブレンド
- 完成量 mL
- 配合材料
- 配合量 μL
- 作成者メモ

### 8.2 単位

現行仕様では、滴数ではなく容量で管理する。

対応単位:

- μL
- mL

表示単位はボタンで切り替え可能。

### 8.3 完成量と配合量

各制作履歴は、完成量が5mLまたは10mLになるように、配合材料の合計μLを持つ。

例:

Sleep Reset 5mL:

- ②ブレンド Woody Restore: 2000μL
- パルマローザ: 1200μL
- ローズウッド: 1650μL
- ローマンカモミール: 150μL
- 合計: 5000μL = 5mL

Morning Focus 10mL:

- ⑩ブレンド Citrus Sharp: 5000μL
- レモン: 2000μL
- ローズマリー: 1800μL
- ペパーミント: 700μL
- ローズウッド: 500μL
- 合計: 10000μL = 10mL

### 8.4 自動計算

現行UIでは、履歴に保存された完成量と配合量をそのまま表示する。

5mL / 10mLボタンを押した場合は、選択中の履歴の比率を維持したまま、指定完成量に換算する。

計算式:

```text
換算係数 = 指定完成量mL / 履歴の元完成量mL
換算後の各材料量μL = 履歴の各材料量μL × 換算係数
```

例:

- 元履歴が5mLで、10mL表示に切り替えた場合: 各材料量は2倍
- 元履歴が10mLで、5mL表示に切り替えた場合: 各材料量は0.5倍

画面上では「入力合計」と「完成量」を表示し、合計が一致するか確認できる。

重要:

- 「滴」は使用しない
- 「基準容量」という別概念は使わない
- 4850μLから5000μLへ補正するような再計算は行わない
- 履歴データ自体が5mLまたは10mLに一致する設計とする

## 9. ヒアリングシート・Googleフォーム連携仕様

### 9.1 目的

利用者が事前にGoogleフォーム等で回答した内容を、香り制作時の確認情報としてカルテに残す。

回答は顧客単位だけでなく、制作履歴単位で保存する。過去の診断・制作履歴を選択した場合は、その制作時点のヒアリング回答、目的、禁忌・注意事項を中央カラムの制作履歴詳細下にある「ヒアリングシート回答履歴」に表示する。

### 9.2 現行デモの実装状態

現行デモでは、16件の制作履歴それぞれにサンプルのヒアリング回答を持たせている。

表示内容:

- 回答元: Googleフォーム / 手動入力
- 回答ID
- 回答日
- ふりがな
- 誕生日
- 誕生日から自動計算した年齢
- 今回の目的
- 欲しい香り
- 香りの好み・避けたい印象
- 持病・体調メモ
- 服薬・医療確認メモ
- 禁忌・注意事項
- オペレーター確認メモ

年齢は誕生日と回答日から自動計算する。現行表示では「回答日時点の年齢」として扱う。

### 9.3 Googleフォーム質問項目案

Googleフォームで取得する主な項目:

- 氏名
- ふりがな
- 誕生日
- 今回の目的

- 好きな香り
- 苦手な香り

目的の選択肢例:

### 9.4 禁忌・注意フラグ

現行デモで扱う禁忌・注意フラグ:

- 妊娠中

- 授乳中

- 喘息・アレルギー傾向

これらは医療診断ではなく、調香前の確認メモとして表示する。該当項目がある場合は、専門家、医師、薬剤師の確認を優先する。

### 9.5 連携方式

本番化時の想定フロー:

1. 利用者がGoogleフォームに回答する。
2. Googleフォームの回答をGoogleスプレッドシートに保存する。
3. Google Apps Scriptのフォーム送信トリガーで、回答内容をJSONに整形する。
4. Apps Scriptからアプリ側APIまたはSupabase Edge FunctionへPOSTする。
5. アプリ側で顧客IDまたは氏名・誕生日から該当カルテを特定する。
6. `hearing_sheets` テーブルに回答を保存する。
7. 制作履歴作成時に `aroma_record_id` と `hearing_sheet_id` を紐づける。
8. 過去の制作履歴を選択したとき、対応するヒアリング回答を表示する。

- `customers`

- ヒアリングシートと制作履歴の永続的な紐づけ

## 15. 一時公開方法

### 15.1 Cloudflare Quick Tunnel

短時間だけローカル画面を共有する場合の第一候補。

特徴:

- ランダムな `trycloudflare.com` URLを発行
- Cloudflareアカウントなしでも試せる
- HTTPS URLになる
- 開発・確認用途向け
- ターミナルを閉じると公開終了
